The root is a Nuxt 4 app (`nuxt.config.ts`) that composes all child feature directories under `app/` through Nuxt's file-system router. Cross-child wiring happens at three levels: (1) shared infrastructure — `@pinia/nuxt` + `@pinia-plugin-persistedstate/nuxt` are registered as global modules so every child page/store shares Pinia state; (2) environment boundaries — `runtimeConfig.public.apiBase` and `tomtomApiKey` expose backend endpoints and the TomTom key uniformly to all children; (3) SSR policy — `routeRules` disables SSR for `/login`, `/forgot-password`, `/pay/**`, and `/tracking/**`, which is how the auth pages and external-iframe routes stay client-only while other features render server-side. `vitest.config.ts` mirrors the Nuxt aliasing (`~` → `./app`) so tests resolve the same module graph as the dev/build pipeline.
