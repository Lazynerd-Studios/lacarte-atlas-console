Three sibling Nuxt `<script setup lang="ts">` pages under `app/pages/`, each self-contained with inline template styles and no shared component imports beyond the app-wide `UIcon` renderer. Layout policy is declared per-page via `definePageMeta({ layout: ... })`: `login.vue` and `forgot-password.vue` opt out of the app shell (`layout: false`) and render a full-viewport card over decorative gradient blobs; `unauthorized.vue` opts into the existing `dashboard` layout. State is entirely local (`ref`/`reactive`); there is no page-level store. Side effects reach outward only through top-level composables/stores: `useApi()` for HTTP calls, `useAuthStore().setAuth(user, token)` to persist tokens on login, `useAppToast()` for success feedback, and `useRouter()` for navigation. `login.vue` bridges the API response (`data.user`, `data.token`) into the global auth store before redirecting to `/`; `forgot-password.vue` POSTs to `/auth/forgot-password` and toggles between form and success states via a `submitted` flag; `unauthorized.vue` is a pure read-only error screen with `router.back()` / `router.push('/')` actions. Dependency direction is one-way: pages depend on the Nuxt runtime and the app's root composables/stores — they do not import each other or any internal component library.
